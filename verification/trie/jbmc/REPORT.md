## Method

- Real classes: JBMC 6.11.0 runs the compiled `rskj-core` classes and their jars at the pinned commit. No `co.rsk.trie.*`, `TrieKeyMapper`, `Uint8/16/24` or `VarInt` class is stubbed or re-implemented. Environment models (`models/`) replace only JDK and library code JBMC cannot execute; each states why it cannot change trie behaviour, and `models-test/` compares them with the real JDK classes.
- Keccak-256 is an ideal collision-free oracle (`models/src/org/ethereum/crypto/Keccak256Helper.java`); properties about concrete digest values are left to the differential tests.
- Every property harness has a negative control that must fail on its own assertion; every RSKIP reading is a separate harness expected to fail, with a reproducer.
- Stubs JBMC substitutes for bodiless methods are listed per result and audited against `models/benign-stubs.json` (`reaudit.py`; conditional entries are checked in each result's log).
- Heavy checks are split into parts whose union is the original check (`gen-splits.py`, trie-put-delete-get 288, keyslice-rebuild-shared-path 173, trie-empty-value-is-delete 144, node-encoding-injective 144, ops-empty-and-null-are-delete 144, ops-immutable 144, ops-delete-recursive 144, ops-canonical-shape 144, node-format-2 132, hash-binds-map 78, trie-message-roundtrip 67, ops-history-independent-hash 67, hash-node-hash 67, node-format-3 67, ops-history-independent 67, store-save-retrieve 48, store-content-addressed 48, store-saved-entries 37, dto-roundtrip-inline 30, orchid-layout 27, orchid-parse 27, key-injective 25, key-storage-key 15, trie-put-get 12, key-strip-leading-zeroes 11, parser-version-not-checked 5, parser-total 5, parser-tree-size-varint 4).
- Runs go through `heavy_run.py` (shared lock, memory watchdog, admission and timeout); each run writes `results/invocation-manifest.json` (argv, classpath and source digests, versions) so a second executor's invocation must be checked against its original reference before `merge-batch.py` is called. The merger itself checks only validation verdicts, not manifest identity.
- [Batch 4 provenance](evidence-b4/README.md): exact original reference/executor match; harness/model sources match commit `6642bf537`. Its selected operation bodies are unchanged, but its aggregate harness classpath is historical, not identical to the current tree.

## Bounds and narrowings

Bounds are recorded per entry in `harnesses.json` and `results/summary.json` (`bounds`, `note`). Narrowings made to fit the time limit, each with its justification:

- `--max-field-sensitivity-array-size 512` on the serialisation-heavy trie parts only affects the precision of symbolic execution (no semantic change).
