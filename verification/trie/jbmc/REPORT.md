## Method

- Real classes: JBMC 6.11.0 runs the compiled `rskj-core` classes and their jars at the pinned commit. No `co.rsk.trie.*`, `TrieKeyMapper`, `Uint8/16/24` or `VarInt` class is stubbed or re-implemented. Environment models (`models/`) replace only JDK and library code JBMC cannot execute; each states why it cannot change trie behaviour, and `models-test/` compares them with the real JDK classes.
- Keccak-256 is an ideal collision-free oracle (`models/src/org/ethereum/crypto/Keccak256Helper.java`); properties about concrete digest values are left to the differential tests.
- Every property harness has a negative control that must fail on its own assertion; every RSKIP reading is a separate harness expected to fail, with a reproducer.
- Stubs JBMC substitutes for bodiless methods are listed per result and audited against `models/benign-stubs.json` (`reaudit.py`; conditional entries are checked in each result's log).
- Heavy checks are split into parts whose union is the original check (`gen-splits.py`, trie-put-delete-get 288, keyslice-rebuild-shared-path 173, trie-empty-value-is-delete 144, trie-message-roundtrip 67, key-injective 25, key-storage-key 15, trie-put-get 12, key-strip-leading-zeroes 11, parser-tree-size-varint 4).
- Runs go through `heavy_run.py` (shared lock, memory watchdog, admission and timeout); each run writes `results/invocation-manifest.json` (argv, classpath and source digests, versions) so a second executor's results are merged only when its invocation is identical (`merge-batch.py`).

## Bounds and narrowings

Bounds are recorded per entry in `harnesses.json` and `results/summary.json` (`bounds`, `note`). Narrowings made to fit the time limit, each with its justification:

- `key-account-key-cached`: cache-hit path of TrieKeyMapper (real JDK HashMap); address with 1 symbolic byte, 19 fixed
- Key universe: multi-key trie harnesses enumerate the 12 keys of `Nondet.KEYS` with symbolic values of fixed lengths (1, 32, 33 bytes); key harnesses use symbolic 20-byte addresses and 32-byte words by leading-zero class.
- `--max-field-sensitivity-array-size 512` on the serialisation-heavy trie parts only affects the precision of symbolic execution (no semantic change).
